# SONIC 局部跟踪评估 v2

2026-10-15。新增训练 checkpoint 的 `g1_kin` 离线动作重建。控制器、夹爪与机器人服务未修改；如果已经安装 tracking v1 观察点，不需要重装。

## 现在的逻辑

```text
人体 SMPL 输入 → SONIC encoder → 实际使用的 64D token
                                   ├→ g1_dyn + 机器人观测 → 控制目标 → 最终指令 → 实际关节角
                                   └→ 离线 g1_kin → ELF3 重建参考 ────────────────┘ 比较
```

主路控制维持原状。记录器捕获真正使用的输入、token、目标和实测数据，工作站在录制结束后跑旁路 `g1_kin`。它不会把重建参考发给机器人，也不在实时控制循环增加一次推理。

主报告为 `analysis/tracking_reference.html`，同屏四条曲线：重建参考、控制目标、最终指令、实际角度。勾选可额外显示过渡处理后的目标。所有角度显示为度，CSV 和模型原始窗口另外保留。

| 比较 | 用途 |
|---|---|
| 重建参考 → 实际 | 相对于模型重建姿态的局部动作跟踪 |
| 最终指令 → 实际 | 执行跟踪偏差 |
| 固定躯干后，参考骨架 → 实际骨架 | 关节角误差在机器人空间中造成的点位置差，mm |
| 已有参考—锚点旋转误差 | 保留原先基于实际 encoder 输入、已做初始 yaw 对齐的朝向诊断 |

每关节分别报告 MAE、RMSE、偏差、P95、最大误差，以及估计滞后。补偿后 RMSE 与同一样本上的未补偿 RMSE 并列，主成绩始终保留原始误差。控制目标可能为动态跟踪提供提前量，不能要求它与重建参考逐点相等。

## 直接使用

原入口已更新，继续运行工作站上的 `outputs/sonic_tracking_20261014.sh --record 60`。
已有本地记录用同一入口 `--analyze 记录目录` 重算即可；最后输出 `HTML_REPORT`。

也可直接执行：

```bash
python3 evaluate.py /实际的本地记录目录
```

工作站依赖：NumPy、ONNX Runtime、Matplotlib。日常分析不加载 PyTorch checkpoint，也不依赖相机、Isaac Sim、网络或 ROS。旁边必须保留原 `sonic_tracking_20261014_v1` 包，复用其记录解析、时间配对和运动学。

## 时间、角度与模型约定

- 使用实际记录的 post-FSQ token，模型 SHA 必须与 `kinematic_manifest.json` 的已验证模型相同。未知/混合模型不套用旧权重，报告显示原因，执行报告和原始数据仍保留。
- 机器人重建窗口为 10 帧、训练间隔 100 ms；SMPL 输入为 10 帧、间隔 20 ms。当前评分只取重建窗口第 0 帧，不把未来帧当作当前目标。
- 训练输出前58列有历史打包方式：先展平为580项，再取前290项为10×29位置、后290项为10×29速度。不能直接逐行取前29列。
- `g1_kin` 输出已经是关节绝对坐标，单位弧度，不再次乘 action scale 或加默认姿态。关节名称与训练配置、记录契约严格一致。
- 保留原 v1 因果配对：实测源时间 → 最近已发布指令 → 该指令之前最近已完成推理，每步不超过50 ms。新增参考使用同一条已配对推理，不使用未来推理、不插值补齐。CSV 给出参考年龄与参考帧号。
- 滞后是参考/指令曲线到实测曲线的匹配估计，不是上游人体采集到机器人的总延迟。静止、小于5°的运动、短记录不给估计；不跨缺帧、控制退出、推理重启或序号断层配对。0–250 ms 范围外的延迟不能由当前搜索确定。
- ROS 时钟跳变时，新参考分析保留缺失状态，避免静默拼接不同时间轴；原始记录不丢弃。
- 原始数组、完整十帧参考和未评分阶段均保留。图像适度抽样，数值统计使用全部有效样本。

## 输出文件

- `tracking_reference.html`：可选关节、显示时段、四条角度曲线、两条误差曲线、两类统计。
- `eval_report.json`：`kinematic_reference_tracking` 保存参考指标、时间定义和模型指纹；既有执行/朝向诊断继续保留。
- `reference_joint_angles.csv`：逐反馈帧、逐关节的参考/目标/指令/实测，评分标记、参考年龄、帧号。
- `reference_joint_metrics.csv`：两类原始误差、滞后及补偿前后 RMSE。
- `kinematic_reference_arrays.npz`：每次推理的完整参考位置/速度窗口、相对锚点旋转6D、token有效标记、会话和帧号。
- `execution_shape_errors.csv`：增加参考→实际的固定躯干骨架距离曲线。

## 指标边界

`g1_kin` 给出模型重建参考，不是独立重定向真值；误差小只能说明实机接近该模型参考，不能独自证明人体重定向正确。

骨架距离使用同一 URDF，并固定两侧 torso 根的旋转和平移，只衡量关节形成的身体形状差异。它不等同于保留整体朝向误差的官方 MPJPE_L。现场 URDF 指纹仍待核对；关节反馈来自驱动，不是外部动捕或原始转子角。

全局根位置与 MPJPE_G 是可选扩展，不作为本轮工作的前提。原离线 `--paired-world` 接口保留，说明见上一版 `sonic_eval_20261015/README.md`。

## 来源与验证

导出使用本地归档 step28800 checkpoint 和原 `BaseModule` 类。其 SMPL encoder、g1_dyn 共24个参数数组与本地部署 `sonic_action_token.onnx` 对应参数完全一致。g1_kin 单独导为 ONNX，CPU 与原 PyTorch 分支在17组合成 token 上对比；最大绝对差约 2.67e-5（混合单位原始输出），详细指纹见 `kinematic_manifest.json`。

离线测试覆盖训练窗口拆分、真实导出数值一致性、错误模型拒绝、坏 token、不使用未来参考、50 ms 已知滞后、两类误差、会话断层、空数据、完整报告生成和原官方公式回归。测试数据明确标为合成，不能当成真机成绩。

维护者可运行 `export_kinematic.py` 重新导出；这一步才需要本地 checkpoint、PyTorch、ONNX、OmegaConf。训练元数据用无操作占位类型读取，不导入训练器、不启仿真。
