# 任务文字如何标注

任务文字是操作员给VLA的自然语言指令，例如：

> 把桌上的红色盒子拿起，放到右侧托盘上。

它描述要完成的任务，不是电机角度、每帧动作解说、推理结果或成功标签。当前程序不会从PICO或视频自动猜任务；由知道示范意图的人填写。

## 录制前填写

本地客户版本读取`tools/customer/site.local.json`，或环境变量`SONIC_SITE_CONFIG`指向的站点JSON。在已有配置中填写这两个字段，保留其余配置：

```json
{
  "training_task": "把桌上的红色盒子拿起，放到右侧托盘上。",
  "capture_profile": "sonic50_latest_rgb"
}
```

这只是字段片段，不是完整站点配置。不要用它覆盖整份site.local.json。

1. 在开始这一条示范前填好任务文字。
2. 按原采集流程开始；启动日志会打印`TASK_INSTRUCTION=...`，核对这句话。
3. 完成所述任务后保存。整条数据使用这句指令，包括A+X暂停前与恢复后的两段。
4. 换任务时，在开始下一条前修改文字。采集子进程启动后已读取的任务不会因中途编辑文件而自动改变。

`training_task`为空时，原始相机测试仍可记录，但标签是Diagnostic占位文本，不能直接用于正式任务训练。已有真机冻结r7尚未安装本地客户版时，不应假定它已读取这份工作站配置。

## 如何保存到数据

configure.py把training_task放入配置的dataset.tasks[].instruction；记录器将它写进原始`meta.json`的task_name。

导出后的`meta/tasks.jsonl`：

```jsonl
{"task_index":0,"task":"把桌上的红色盒子拿起，放到右侧托盘上。"}
```

Parquet中每一行保存`task_index=0`；GR00T加载器据此取出上面的文字。`episodes.jsonl`也记录本条的任务列表。相同任务的多次示范可以共用同一编号，不必每帧重复手写文字。

若已有记录的任务文字漏填或写错，可在**确认这条视频确实演示该任务之后**离线导出时指定：

```bash
python tools/gr00t_dataset/export_dataset.py /实际原始episode目录   --task "把桌上的红色盒子拿起，放到右侧托盘上。"   --output /新的训练数据目录
```

命令只给本次导出的数据赋标签，不修改原始录制。不能把内容不同的多条示范一起套同一个错误任务；也不会因此把旧30Hz原始记录变成50Hz。

## 写多具体

- 合适：“把红色盒子放到右侧托盘上。”——动作、对象和目标清楚。
- 太含糊：“操作一下。”“测试。”“搬东西。”——难以对应任务。
- 不需要逐帧写“肩抬10度、夹爪闭到0度”；这些执行信息已经在动作数据里。
- 成功/失败是另一项质量信息；一句任务指令不能证明任务完成。
- JSON支持中文。任务表达应与实际示范和之后给模型的指令一致，不能自动把“用户按了保存”视为语义成功。

官方同样由人提供文字：`run_data_exporter.py`的`--task-prompt`传给导出器的task参数；不是视觉自动标注。[官方源码](https://github.com/NVlabs/GR00T-WholeBodyControl/blob/main/gear_sonic/scripts/run_data_exporter.py)。

## state、action与夹爪角度

`observation.state`是这一时刻电机的实测位置；`action.wbc`是下发的目标位置。比如目标300°、实测240°，两者分别保存5.236 rad和4.189 rad。夹爪都来自已用的真实控制/反馈链路，不重新定义零点或传动坐标。

归一化统计从保存的这些角度数据计算；它是模型内部数值缩放，不是新标定。模型输出反归一化后恢复成电机rad；若接同事demo的度数接口，边界处换算为度。不能套用旧仿真开度数据的统计。

## 50Hz数值与30Hz相机

官方相机默认30Hz，导出循环默认50Hz；有新画面才更新latest_image_msg，否则采集循环继续用缓存。本库`sonic50_latest_rgb`采用同样的图像复用逻辑。

本机ROS链路按实际收到的live推理时刻保存数值，每个推理序号至多一次，缺失不补造；匹配同次身体指令与反馈，并选各相机此前最近画面。保留原有源时间缓冲以应对ROS传输延迟。图像年龄上限100ms，未来画面/更老的图像不接受，记录源时间、序号和复用标记。A+X暂停后不允许复用暂停前图像。

新示例配置默认sonic50_latest_rgb；已有未填写capture_profile的站点保持head30，须显式切换。历史head30记录仍按原规则读回。50Hz定时器不是帧率保证，实际有效率取决于所有输入，需要现场读回验收。

实现已通过合成源数据、真实写入器和GR00T加载链路的离线测试；机器人尚未部署。数据列与文件见[数据字典](GR00T_N17_DATA_FORMAT.md)。
